## 후속 — 글자 크기 매핑 검토 (2026-10-14)

디자인 px ≈ 앱 sp 매핑 실측 대조(호스트):

- 본문 0.84–0.88rem(≈13.4–14.1px) ↔ 13–14sp · 제목 0.95–1rem(≈15.2–16px) ↔ 16sp ·
  캡션 0.75–0.78rem(≈12–12.5px) ↔ 12sp — 일치 범위(앱이 하한에서 약간 큰 쪽 = 현장 가독성 우선).
- 레일 각주 0.63rem(≈10.1px) ↔ 10sp(`rail_note`) 일치. 이벤트 범례는 0.7rem(≈11.2px) 기준으로
  **10sp → 11sp 상향**(유일한 이탈값 수정).
- 실기(7″·햇빛·장갑) 재보정은 A9-4 항목으로 유지.

## 전달 화면·검증 보충 (2026-10-14)

C67의 당시 구현/검증 기록은 위와 같이 보존한다. 이 절은 현재 전달된 화면 구조와 후속 UI 조정을 기록한다.

### 화면 구조와 상태 표현

- 조종 콕핏은 상자형 상태 카드 대신 영상 위의 2행 무박스 상태 띠를 쓴다. 순서는 KSI 로컬 기록,
  MOP/하트비트, 기체 연결, 인터넷, 영상 입력, 레코더 기록, 로컬 증거, 관측 수신이다.
  문제(■)·주의(▲)·정보(·) 표식은 출처별 사실에 붙고 색만으로 의미를 전달하지 않는다.
- Android 상태 띠는 현재 7칩(KSI/MOP/기체/인터넷/영상/레코더/로컬 증거)이며 AI 관측 신선도는 하단
  텍스트로 표시한다. 8번째 관측 수신 칩 추가는 7″ 폭 제약을 A9-4에서 검증 후 결정한다(G6).
- 우선 확인 문구는 별도 줄바꿈 영역이며 각 사실 상세를 숨기지 않는다. AI 관측 지연은 표시 지연이지
  비행 판정이 아니고, 영상 입력 지연은 상태 띠에만 나타나며 비행 경고로 승격되지 않는다.
- 조종 화면의 집중 보기에서도 상태 띠와 `[SIMULATED]`를 유지한다. MOP 연결/해제/미확인 재전송은
  화면의 `MOP` 토글에서 열며, HTML 시연은 실제 전송하지 않는다.
- 영상은 미연결/연결 중/신호 없음/최근 입력/입력 지연/수신 시각 미확인을 구분한다. 인코딩 입력 수신은
  디코딩·화면 표시 증명이 아니다. 최근 입력일 때 중앙 안내를 걷어 영상 면을 비우되, 표시 상태 미확인 문구를 남긴다.
- 기록 검토에는 사건 0건인 시뮬레이션 비행이 있다. 사건 이전/다음과 의견은 비활성화되며,
  “사건 없음”을 “안전 확인”으로 바꾸지 않는다. 알 수 없는 로컬 증거 수/동기화 상태도 0건과 구분한다.
- 기록 없음 시나리오는 콕핏 비행 ID를 지우고 레코더를 요청/쓰기 없음으로 표시한다.
- 브라우저 기본 예시는 영상 상태와 무관하게 레코더 쓰기 증거를 별도 표시한다: 녹화 요청 예시, writer 수락 샘플 0.
  입력 프레임 수신은 저장 성공을 뜻하지 않는다. 오류 예시는 과거 구간 실패이고 현재 영상 입력/레코더 쓰기 상태와 독립인
  시뮬레이션 예시로 표시해, 입력이 없는 현재 구간에서 쓰는 것처럼 보이지 않게 한다.
- Android에는 같은 목적의 2행 상태 띠, 줄바꿈되는 우선 확인 영역, 독립 운용 상세 패널이 있다.
  콕핏 버튼은 48dp 이상이다. `MainActivity`는 부모 소유 `VideoFreshnessModel`을 1초 UI 틱으로 다시 평가하고
  입력 프레임 수/시각과 writer 수/실패 사실을 전달한다. 최근 입력일 때 중앙 안내는 SurfaceView를 가리지 않지만
  표시 상태는 미확인으로 남긴다. stale cue는 비행 경고가 아닌 영상 입력 사실로만 노출한다.
  기체/MOP/인터넷/영상/레코더/증거 상태는 각각 독립 표시한다.

### 브라우저와 Android의 동작 경계

- `design/rc-pilot-shell/field-shell.html`은 다섯 목적지(조종, 임무, 기록, 증거, 설정)와 설정 하위 시스템
  진단을 제공하는 시뮬레이션이다. 영상/MOP/임무/서버 버튼은 설명 상태만 바꾸며 실제 API, 기체, 저장소를 호출하지 않는다.
  표본 값은 `[SIMULATED]`로 구분한다.
- Android는 데모 토글을 사용하지 않는다. 실제 `RcSession`, 링크, 로컬 증거 저장소와 부모 소유 비디오 포트/모델의
  보고 사실을 표시하며, 이 UI 변경은 API·권한·저장/동기화 계약을 바꾸지 않았다.
- 서버 `COMMITTED`는 동기화 확인 사실로만 표시한다. 사건 0건은 안전 증명이 아니며 `frameMappingVerified=false`일 때
  영상 박스를 표시하지 않는 규칙을 유지한다.

### 검증과 한계

- 최신 브라우저 파일을 로컬 Chrome에서 실제 렌더링하고 마우스 클릭/키보드 입력으로 확인했다.
  1024×768, 390×844, 1280×720에서 다섯 목적지/설정 하위 진단을 확인하고, RC 가로 논리 화면 960×600에서는
  콕핏을 추가 확인했다.
  목적지 간 전환에서 수평 넘침은 관찰하지 않았고, 콘텐츠가 긴 임무·기록·증거·설정/진단 화면은 의도한 스크롤을 사용했다.
  콕핏 상태 띠와 우선 확인 문구는 390×844, 1024×768, 960×600, 1280×720에서 겹치지 않았다.
- 확인한 입력/상태: 메뉴의 키보드 포커스 이동·경계 순환·Escape 복귀, 집중 보기 상태 유지,
  MOP 도크의 키보드 열기/포커스/Escape 닫기, 기록 탭의 방향키/End, 0건 사건 비활성 조작,
  기록 없음에서 비행 ID 제거와 레코더 요청/쓰기 없음, 영상 연결/신호 없음/최근/지연/미확인,
  MOP 끊김 및 과거 레코더 오류 표시.
- Coordinator의 고립 세션 smoke에서 발견한 브라우저 표본 불일치를 수정했다. 최신 1024×768/390×844 렌더에서
  영상 미연결 + writer 수락 샘플 0을 확인했다. 최근 입력 표본에서도 녹화 요청과 writer 샘플을 별도 표시하고,
  오류 표본은 현재 writer 진행이 아닌 독립된 과거 구간 실패로 재확인했다.
- axe-core 브라우저 감사는 위반 0건이었다. 대비 규칙 1개는 배경 그라데이션/기호 때문에 자동 판정 불완전으로 남아
  전체 수동 색 대비 판정을 완료했다고 주장하지 않는다.
- 브라우저 입력 확인은 마우스/키보드 에뮬레이션이다. 실기 터치·햇빛·장갑 검증은 하지 않았다.
  이 환경에는 Android 에뮬레이터/기기가 없으므로 Android 렌더링, 실제 터치, 스크롤/겹침은 검증하지 않았다.
  여기서는 XML well-formedness, 콕핏/내비게이션 48dp 주요 컨트롤의 구조 검사, HTML JavaScript 구문과 diff 공백 검사를 했다.
  전체 Gradle lint/build는 동시에 실행하지 않았으며, 부모가 추가한 API 26/27 권한 protectionLevel fallback과
  Android XML의 `\?` 이스케이프를 보존했다. 최종 통합 Android lint/APK/unit run은 coordinator 게이트로 남긴다.
