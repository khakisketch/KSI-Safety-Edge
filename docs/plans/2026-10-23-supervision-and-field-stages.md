# 감독 화면·현장 순찰 — 3·4단계 인수 계획 초안

상태: **2026-10-23 감독형 UI 구현 승인·진행 중. 실기 렌더·위험 경보 운용 승인 아님.**
선행: [1단계 자동 관측](2026-10-23-autonomous-observation-stage1.md),
[2단계 능동 재관측](2026-10-23-active-reobservation-stage2.md).
`field-shell.html`과 Android 화면을 감독형으로 변경한다. 기존 D1/D6/D7의 영상·물리 조작 우선 방향은 유지한다.

## 1. 3단계 — 기본 화면의 네 가지 질문

| 질문 | 표시해야 할 사실 | 오해 방지 |
|---|---|---|
| 관측이 진행되는가 | 실제 AI 실행과 입력 품질 | 시작 요청·`running` bool만으로 분석 중이라 하지 않음 |
| 카메라를 누가 조작하는가 | 실제 제어 주체·자동 허용·조절 실행 여부 | `카메라: 조종자`와 `AI 관측: 실행 중`이 공존 가능 |
| 원본이 보존되는가 | Manifold 로컬 내구 보존·결측/실패 | RC 수신·Core 보관·Alert 전달과 합치지 않음 |
| 지금 개입해야 하는가 | 승인된 위험 알림 또는 중요한 관측/저장 장애와 행동 | 모든 후보·판정불가를 검토 의무로 만들지 않음 |

- 큰 영상+미니맵, 필수 비행 상태와 물리 조작을 유지한다. 비행 화면에 매 후보의 3응답 패널을 자동으로 열지 않는다.
- 자동 카메라가 없거나 사용할 수 없어도 기본 관측을 정상적으로 운용할 수 있어야 한다.
- 재관측 진행은 작은 상태로 알린다. 조종자 영상의 화각이 바뀐다는 사실과 관측 한계를 숨기지 않는다.
- 수동 양보와 AI 관측 중지는 다른 행동이다. 제어 주체/실행 보고가 없으면 미확인으로 표시한다.
- 자율 감독 단일 흐름(2026-10-23 합의): 수동 카메라는 독립 표시 축일 뿐 별도 제품 트랙이 아니다. 수동용·자동용을 따로 만들지 않는다.
- SHADOW 실증은 운용 경보와 명확히 구분한다. 무알림·0건은 안전이나 유효 관측 완료의 증거가 아니다.
- 중요 알림의 근거 장면·시각·위치 품질·필요 행동은 요청 시 확인할 수 있게 한다.
  영상/지도 오버레이는 해당 프레임·공간 정합이 검증된 경우에만 사용한다.

## 2. 결과·검토와 알림

- 관측 기록에는 관측→평가→추가 관측→원본 증거를 연결하고, 확정 위험 사건과 판정불가·공백을 구분한다.
- 사람의 확인/보류/전달은 사후 검토 또는 중요한 예외 상세에서 선택적으로 기록한다.
  자동 평가 완료를 사람의 응답으로 대체하지 않으며, 미응답을 확인/기각으로 간주하지 않는다.
- Alert 생성은 관측/평가 완료 이벤트와 별도 정책으로 결정한다. 같은 상황은 에피소드로 묶어 중복 알림을 억제한다.
- 위험 알림과 운용장애 알림은 근거·심각도·조치가 다르다. 중요한 장애를 일반 후보와 함께 조용히 숨기지 않는다.
- 수신 대상·라우팅·권한·재시도 정책은 구현 전 특정한다. 오프라인이면 로컬 알림과 전송 대기를 구분한다.
- 알림 생성·전송·상대 수신·사람 확인·현장 조치는 별개다. Core 보관 영수증을 알림 수신 영수증으로 쓰지 않는다.

## 3. 3단계 렌더·상호작용 인수

| 상태 | 실제 화면에서 확인할 결과 |
|---|---|
| 자동 카메라 없는 기본 관측 | 사람의 후보 확인 없이 관측과 원본 보존 사실을 감독 가능 |
| AI 관측 실행 + 수동 카메라 | 분석 중·조종자 제어·자동 조절 해제의 독립 표시 |
| DJI 임무 카메라 점유 | 실제 보고 범위만 표시. KSI 내부 허용을 기체 점유권으로 오표시하지 않음 |
| 관측 불가·저장 실패·링크 유실 | 영향을 받은 축과 필요한 행동 표시, 기본 비행·수동 카메라 유지 |
| 후보 다수·일반 판정불가 | 큰 패널/모달·매건 확인 요구 없이 기록 접근 가능 |
| 승인된 경보의 모의 입력 | 근거와 필요한 행동 접근 가능, 확인이 위험 해소로 바뀌지 않음 |

웹 합성·Android 호스트·네이티브 렌더·실제 터치/물리 입력·사용자 인수는 분리한다.
768×480 및 usable 768×464 논리 공간, 주야간, 포커스/복귀·가림·48dp 조작을 실제 렌더로 확인한다.
현재 RC 접근 보류를 해제하지 않으며, 웹 캡처를 최신 Android 실기 증거로 사용하지 않는다.

## 4. 4단계 — 현장 순찰 인수

1. **지상 기능 확인:** 카메라 지원·명령 결과·수동/임무/PSDK 충돌·정지/양보를 해당 기체/펌웨어에서 확인한다.
2. **순찰 중 기본 관측:** 정해진 경로를 변경하지 않고 1단계 관측·평가·판정불가·원본 보존을 검증한다.
3. **허용 구간의 능동 재관측:** 별도로 2단계 작업을 수행하고 경로 준수·카메라 충돌·대상 연결·관측 공백을 확인한다.
4. **규칙별 현장 평가:** 대표 조건과 독립 정답/holdout으로 탐지 정확도뿐 아니라 영상 시간 정합·공간좌표·대상 간 거리·위험 기준·경보 지연·불확실성을 함께 측정한다.
5. **경보 승인:** 검증한 규칙/운용 조건에 한해 별도 ACTIVE 승인. 재관측·경로 수행 성공으로 승격하지 않는다.
   관측·저장 실패를 알리는 시스템 경고는 위험 경보 승인과 별개이며, 위험 판정이 시험 단계여도 원본을 저장하지 못하면 조종자에게 알린다.

제품 지표는 경로 통과율 자체가 아니라 **유효 관측 범위, 신뢰 가능한 평가와 판정불가의 비율/원인,
근거·전후 맥락의 완전성, 필요한 사람 개입, 알림/보존의 실제 상태**다.
분석하지 못한 구간·실패한 평가를 제외해서 수치를 좋게 만들지 않는다.

Pilot 2/MSDK 앱은 한 운용의 지상 환경 선택 문제다. 현재 KSI 앱을 유지하며 엔진을 독립시킨다.
Pilot 2 전환 시에는 준비/시작·오프라인 기록·증거 중계·영수증 표시 책임의 대체 경로를 별도 검증한다.
임의 앱 전환·동시 운용·위젯만으로 기존 책임을 충족했다고 가정하지 않는다.
