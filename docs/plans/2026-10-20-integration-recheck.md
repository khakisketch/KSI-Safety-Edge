# 통합 재검토 — 중간 모듈 통과와 제품 인수를 구분

실제 실행 날짜: 2026-10-20. `2026-10-21-edge-operation-contract.md` 등 기존 파일의 날짜는 선행 작업 라벨이다.
사용자 승인 범위: RC↔Manifold 운용·관측·오프라인 증거 보존·복구·Core 대조의 개발 개선 계속.

## 보존하는 결정

- 첫 위험은 사람–중장비 접근, 초기 대상은 지정 작업구역 침입 SHADOW. 절대거리 수치나 ACTIVE를 새로 승인하지 않는다.
- MOP 단절 중 유효한 로컬 관측은 계속하고 결과를 영속 기록한다. 입력 장애는 별도 사건이다.
- COMMITTED는 보존 성공이다. 실행·공간 판단 성공이나 L1 실기 인수가 아니다.
- 기존 계약·검증 원본·사용자 작업 트리를 보존한다. 신규 대응 계약은 별도 파일과 API 확장 명세로 분리한다.
- 운용 화면 우선 진입·GPS 추천/조종자 확인은 최신 **제안**이다. 현장 경계·정확도 자료 없이 자동 선택을 구현하지 않는다.

## 코드 재검토에서 확인한 실패 모드와 조치

| 실패 모드 | 필요한 조치 | 검증 범위 |
|---|---|---|
| 단절 중 EmitTick가 BuildTick 전에 반환 | 연결과 분리된 영속 증거 큐, 동일 ID 재전송·ACK 이후만 전달 확정 | 실제 파일·재생성·재접속 모의, SDK 재접속은 실기 별도 |
| START/STOP 고정 순서와 APPLY 동시 도착 소실 | 원자적 명령 스냅샷과 최종 수신 의도 유지 | 같은 poll 안의 두 순서·동시 APPLY·중복 START |
| 프로세스 재생성 시 boot/runtime ID 재사용 | 실제 프로세스마다 새 실행 식별자, 과거 기록은 원래 출처 유지 | 새 프로세스 경계 모의·과거 실행 자동 복원 금지 |
| 엔진 설치 전에 APPLIED/증거 출처 변경 | 실제 설치 영수증에만 번들·정책 출처 연결 | 거부·파싱 실패·재시작·동시 입력 |
| RC가 STARTING 등을 STOP 확인으로 취급 | 정확한 STOPPED 보고와 요청/부트/설정 대조 | 중지 대기·지연 보고·다른 설정의 보고 |
| 영상 무입력 시 이전 건강 상태 유지 | 프레임과 독립적인 입력 건강 검사 | 첫 프레임 미수신·중간 단절·복구 |
| 실제 모델 digest 부재 | 실제 엔진 파일 해시와 모델 프로필 대조 | 파일 바이트 기반 해시, 빈/가짜 digest 금지 |
| 화면 렌더마다 마지막 확인 시각 갱신 | 새 수신 식별자에만 시각 래치 | 시간 경과·반복 렌더·링크 단절 |
| false/null 차이로 판정 반복 fsync | 동일 사실 스냅샷 비교·분류·저장 | 반복 렌더에 추가 저장 없음 |
| 최종 영상/마감 전에 업로드 예약 | STOP 확인 또는 명시적 미확인 로컬 마감 → 영상 마감 → 인제스트 → 마감 원장 → 업로드 | 생산 코드의 주입 가능한 마감 순서 시험 |
| 이미 COMMITTED 이후 늦은 대응 건너뜀 | 앱 스케줄러부터 별도 대응 영수증까지 연결 | 실제 Core E2E·재시도·재시작·이전 Core 404 |
| 구조화 대응 200 응답을 영속 확인으로 오해 | durable=true·배치 ID·대상 ID 집합 대조 후 영수증 저장 | 거짓/불완전 200은 pending 유지 |
| 여러 미분류 FLIGHT_LOG가 같은 legacy 계보로 묶임 | 알 수 없는 계보는 아티팩트별 보존 | 번들·마감 원장 둘 다 required manifest에 남음 |
| 선택 후보와 최신 후보의 시각/boot 혼동 | 선택한 사건의 실제 수신 영수증 사용 | 이전 boot의 사건 선택·누락 영수증 거부 |

위 표는 구현 체크리스트이며 아직 모두 통과했다는 뜻이 아니다. 최종 소스·명령·출력에 맞춰 결과를 판단한다.

## 재사용·검증 한계 보정

- 선행 응답에서 “Platform 코드는 전혀 없고 스키마로만 재사용 가능”이라고 한 것은 과도했다.
  기존 재사용 감사는 `frame_queue`·PSDK 글루 등의 실제 채택 이력을 보유한다. 그 이력과 불변 원칙을 재사용한다.
- “PSDK는 이 호스트에서 빌드 불가”도 재확인 결과 단정할 수 없다. 공식 PSDK 3.16.0의 aarch64 라이브러리를
  임시 경로에 확보해 플레이스홀더 자격증명으로 실제 앱 컴파일·링크에 성공했다. 실제 키나 기체에 연결하지 않았고
  플레이스홀더 실행은 SDK 초기화 전 exit 2로 거부되었다. TensorRT 실행·DPK 설치·장비 통신의 증거는 아니다.
- 현재 ADB 장치는 없고 에뮬레이터 실행기도 확인되지 않았다. XML/호스트 시험 및 HTML 캡처는 Android 실기 렌더를 대신하지 않는다.
- 서명 키·운영 인증/보존 정책·공간 정확도와 ACTIVE 승인은 별도 게이트다. 이를 자동 설정하거나 통과로 만들지 않는다.
