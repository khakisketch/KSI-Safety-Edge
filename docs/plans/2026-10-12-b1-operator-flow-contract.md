# B-1 — 조종 화면 동선·상태 계약

작성: 2026-10-12 · 갱신: 2026-10-14 · 상태: **상태 계약·요약 모델 구현.
실기 렌더·터치·현장 사용성은 A9-4(장치 입력 후) 검증 대기**

## 목적과 경계

- 목적: 조종사가 화면 하나에서 **"지금 무슨 일이 일어나고 있는가 / 내가 무엇을
  해야 하는가"**를 오해 없이 안다. 상태는 실제 세션 사실에서만 계산하며(추측·
  허위 없음), 없는 상태를 "정상"으로 보이게 하지 않는다.
- 이 문서는 **동작·문구 계약**이다. 시각 디자인(레이아웃·색·타이포·터치 크기)은
  디자인 작업 공간(OpenDesign)이 소유하며, §디자인 위임의 범위·보존 제약이 그
  위임 조건이다.
- 구현: `android-rc/rc-app/src/main/java/ksi/safetyedge/rc/OperatorStatus.kt`
  (순수 모델) + `MainActivity.renderOpsStatus`(상단 상태 요약).
  UI는 이 항목을 그대로 렌더링만 하고 스스로 판단하지 않는다.
  호스트 시험: `android-rc/rc-app/src/test/java/ksi/safetyedge/rc/OperatorStatusTest.kt`.

- "로컬 증거 없음"은 완료 세그먼트가 아직 없다는 사실이다(롤오버·비행 종료 시
  확정). 이것을 "사건 0건"이나 "기록 실패"로 뭉개지 않는다.

- 임계값(하트비트 10s·관측 5s)은 **표시 지표**다. 안전 판정이 아니며, "데이터
  없음"을 "안전"으로 바꾸지 않는다.
- 서버측 업로드 상태(uploaded 등)는 RC에 없다 — 로컬 미동기화 카운트까지만
  표시하고 서버 상태를 추측하지 않는다.

## 화면 동선 (조종사 행동 순서)

1. **임무 준비**: Core 주소·토큰 설정 확인 → 임무 동기화 → 번들 선택.
   실패 시 그대로 오류 표시(성공으로 표시 금지).
2. **비행 시작**: 번들로 비행 시작. 시작 즉시 녹화가 시작되고 증거 수신이
   쌓인다. 비행 없는 상태에서 시작 표시 금지.
3. **비행 중**: 상단 상태 요약에서 ■/▲ 항목을 먼저 읽고 행동. 관측 공백·
   하트비트 지연·링크 끊김은 사실대로 즉시 보인다.
4. **비행 종료**: 종료 시 녹화가 finalize되고 세그먼트가 지역 보관된다.
   재시작해도 녹화 재개(이전 구간 손실은 문구로 고지).
5. **동기화**: 인터넷이 있으면 자동(완료 로컬 데이터 재동기화 예약). 미동기화
   수는 숨기지 않는다.
6. **서버 검토**: 안전관리자는 Core `/review`에서 비행·증거를 검토(별도 문서:
   review console). 사건 0건 비행도 세션 증거가 검토 가능해야 한다.

## 표시 금지·오해 방지 규칙

- 사건 0건 ≠ 안전: "사건 0건 — 정상 기록일 수 있음 / 안전 확인 아님" 문구 유지.
- 관측 공백은 공백으로: `skipped_frames > 0`이면 "관측 공백 N프레임(요약 기준)".
- SIMULATED는 숨기지 않는다: 시뮬레이션 링크·영상은 해당 항목에 [SIMULATED].
- 하트비트 미수신을 "정상"으로 표시하지 않는다(연결 중과 구분).
- 기체 미연결/알 수 없음은 링크 보고 사실과 독립적으로 표시(합쳐서 "연결" 금지).
- 미동기화 증거 수를 숨기지 않는다: 비행 중에는 상태 요약이, 비행 종료 후에는
  비행 기록 섹션(synced= 표기)이 보인다. 요약 헤더로의 승격 여부는 디자인
  위임과 함께 판단한다(아래 미완 참조).

## 미완/후속 (정직 기록)

### 2026-10-14 현장 보조 화면 정리

- DJI Pilot 2가 비행 조종의 기준이다. KSI의 비행 기록 존재를 실제 이륙/비행 상태로
  해석하지 않는다. 비행 중 AI 사건 선택·상세 해석은 제거하고 사후 기록 검토로 이동한다.
- 주 화면은 출처별 상태 띠로 유지하며, 기록 실패는 우선 표시한다. 세부 조치와
  진단은 필요 시 열 수 있지만 비행 중 조종자에게 즉각적인 KSI 조작을 요구하지 않는다.
- 영상 수신은 `VideoFreshnessModel`의 RC monotonic 수신 경과시간으로 갱신한다.
  인코딩 프레임 수신은 실제 화면 표시 성공이나 촬영시각의 증거가 아니다.
- 레코더 요청 상태와 실제 쓰기를 분리한다: 0 sample=입력 대기, 일부 구간 실패=녹화 오류.
  뒤의 구간 복구가 이전 구간 실패를 지우지 않는다. 표시가 바뀌어도 저장/업로드 계약은 불변이다.
- 위 항목의 소프트웨어 시험은 실기 렌더·햇빛·장갑·물리 영상 검증을 대체하지 않는다.

- 초기 B-1 증분은 상태 계약에 한정했다. 이후 C67 및 10/14 화면 개선으로
  섹션 재배치·시각 계층·비행 후 흐름을 연결했으며 실기 사용성 검증은 남아 있다.
- 비행 종료 후 대기 중 동기화는 비행 기록·증거 화면에서 로컬 상태로 확인한다.
- 실기에서 상태 요약의 임계값(10s/5s)이 현장과 맞는지 확인 후 조정 여지.
- 시간 정합(RECEIVE≈촬영시각)은 기존 계약대로 별도 측정 전까지 미주장.
