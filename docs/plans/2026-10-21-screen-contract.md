## 1. 실기에서 확정된 화면 사실

실제 RC Plus 2 (tailscale 네트워크 ADB `[REDACTED: tailscale endpoint]`)에서 실측했다.

| 항목 | 실측값 |
|---|---|
| 기기 | DJI RC PLUS 2 (rc701) · Android 11 (API 30) · arm64-v8a |
| 물리 화면 | 1200×1920 (회전 시 1920×1200) · **density 400** |
| 앱 뷰포트 | **1920×1160 px** = **768×464 dp** |
| 48dp 터치 타깃 | **120px** |

→ 설계 문서의 "1920×1200 = 48px=48dp 가정 금지"가 **실측으로 대체**된다. 이제 모든 레이아웃
판단은 **768×480dp** 기준으로 한다. 1920px 웹 캔버스는 dp 공간의 2.5배 축척이다.

## 2. D1 — 진입

- 앱 실행 → **관측 페이지**(`pageObserve`).
- 활성 KSI 세션이 있으면 그 세션으로 복귀, 없으면 "준비 대기"로 열리고 **현장 확인 카드**가 보인다.

## 3. D2 — 현장 확인 카드 (선택 기능)

- 내용: GPS 기준 후보 1개 + 판단 근거 + `[이 현장으로 준비]` + `[다른 현장 선택]`.
- **자동 확정 금지.** 후보가 없으면 "현장 선택 필요"만 표시한다.
- **위치 출처를 구분**한다: `기체 위치(MSDK)` / `RC 자체 GNSS` / `미확인`.
- **인식 실패가 관측·기록을 막지 않는다.** 현장 미확정은 "어느 현장의 정책인지"만 불명확하게 만든다.
- 데이터 경로: Core `Site`에 중심점/반경 추가(`center_lat`, `center_lon`, `radius_m`).
  위험구역 다각형과 **다른 것**이며 현장 경계 대신 쓰지 않는다. 좌표가 없는 현장은 후보가 아니다.
- 위치 권한: RC Plus 2에 `location.gps` 기능이 있고 시스템이 이미 GPS를 쓰고 있다.
  앱 권한 선언은 아직 없다(D2 실사용 시 추가).

## 7. 실기 렌더에서 발견·수정한 결함 (2026-10-21)

호스트 XML 시험으로는 보이지 않았고 **실제 1920×1200 @400dpi 렌더에서만** 드러났다.
증거: `docs/verification/evidence/2026-10-20-rc-native-render/`.

1. **명령 데크 소멸**: Edge 실행 상태 패널이 478px를 먹어 우측 열(500px)을 소모,
   `opsDeckScroll`에 **22px**만 남음 → 이륙·착륙·RTH·사진·녹화 버튼이 사실상 닿지 않음.
   → 패널 5줄을 각 1줄로 압축(말줄림) + 상태 줄과 중복되는 제목줄 제거 → 데크 **246px** 확보.
2. **버튼 라벨 줄바꿈**: 12sp 라벨이 3열(60dp 폭)에서 "기체 녹화"가 2줄로 깨짐.
   → 명령 그리드를 **3열 → 2열**(95dp/버튼) 재구성, 라벨 축약("● 녹화", "▼ 짐벌").
3. **현장 확인 카드가 명령 조작 공간을 밀어냄**: 우측 열 고정 영역에 두면 데크가 0px가 됨.
   → 카드를 **명령 데크 안(스크롤 가능)** 으로 이동. 레이아웃 계약 시험도 구조 변경에 맞춰 갱신.
4. **위치 권한 중복 선언**: 앱이 `ACCESS_FINE_LOCATION`을 다시 선언하니 권한 주체가 둘이 되어
   `pm revoke`가 성공(종료코드 0)해도 앱은 granted 로 남았다(DJI MSDK AAR이 이미 선언).
   → 앱은 권한을 **요청만** 하고 **선언하지 않는다**. 실기에서 권한 거부 후에도
   비행·AI 관측·기록이 계속 동작함(추천 없이 수동 선택)을 확인했다.

### 7-1. 판정 주의 (이 실기에서 배운 것)

- `dumpsys activity top`의 뷰 좌표는 **부모 기준 상대좌표**다. 실제 화면 좌표가 아니다.
  관측 화면의 명령 데크는 절대 y≈780~1030에 있다.
- `input swipe`는 이 기기에서 정상적으로 스크롤한다(시스템 설정 앱으로 대조 확인).
  "스크롤이 안 된다"고 판단하기 전에 **(a) 절대좌표로 환산 (b) 시스템 UI와의 대조**를 먼저 할 것.
  처음의 "스크롤 불가" 판단은 상대좌표 스와이프에 의한 **오판**이었다(앱 결함 아님).

> 규칙(앞으로): 48dp 요소·12sp 라벨 조합은 **768dp 폭**에서 검토한다. 1920px 캔버스 시안은
> dp 공간의 2.5배 축척이므로, 시안만 보고 "들어간다"고 판단하지 않는다.

### 7-3. 권한 관련 실기 발견 3건

1. **앱은 위치 권한을 선언하지 않는다.** DJI MSDK AAR이 `ACCESS_FINE_LOCATION`/`ACCESS_COARSE_LOCATION`을
   선언한다(merged manifest로 들어옴). 앱이 다시 선언하면 **권한 주체가 둘**이 되어
   `pm revoke`가 성공(종료코드 0)해도 granted 로 남는다. → 앱은 **요청만** 한다.
   (bench flavor 에는 DJI AAR이 없어 위치 권한이 아예 없다 → 그때는 요청도 불가.)
2. **이 기기에서는 `pm grant`/`pm revoke`/`pm clear`가 실질적으로 무효다.** 종료코드 0을 반환하지만
   상태가 바뀌지 않는다(DJI 잠금 시스템). 권한은 반드시 **시스템 대화**로만 바뀐다.
   → 실기 검증은 "이 위치로 현장 찾기" 버튼 → 시스템 대화 경로로 해야 한다.
3. **"이 위치로 현장 찾기"는 위치 권한만 요청해야 한다.** 위험 권한 일괄 요청 헬퍼는 DJI AAR가 선언한
   **전화·사진/미디어 권한까지** 같이 물어 조종자를 혼란스럽게 한다(실기기에서 확인).
   → 전용 헬퍼(`requestLocationPermission`)로 위치만 요청한다.

## 9. 남는 것 (정직)

- **DJI SDK 실등록 미검증**: 우리 패키지(`ksi.safetyedge.rc`)용 앱 키가 없다. 키는 **패키지명**에 묶이므로
  형제 프로젝트의 키(`com.dji.sampleV5.aircraft`)는 재사용할 수 없다.
  → `android-rc/local.properties`의 `dji.apiKey`에 **우리 패키지용 키**가 필요하다(커밋 금지).
- **Manifold 3 실기 미접속**: [REDACTED: manifold LAN address]이 **RC에서도 호스트에서도 무응답**(ARP 실패).
  RC·호스트·매니폴드의 eth0가 모두 [REDACTED: private /24] 사내망이므로 배선·전원 문제다.
  **RC의 USB [REDACTED: USB device]는 매니폴드가 아니다** — 인터페이스 11개가 전부
  class 0xff(厂商 정의)·sub 0x43이고 **네트워크 인터페이스가 하나도 없다**
  (USB로 붙은 리눅스 기기는 CDC/RNDIS를 낸다). 시리얼도 `[REDACTED: serial]` 더미다.
  → RC 내부 USB 장치(DJI Virtual Joystick과 짝을 이룬다). 이전 기록의

  매니폴드의 역할·책임·기능 자체의 정본은 `docs/plans/2026-10-21-manifold-role-contract.md`다.
- **기체·영상 실물 미검증**, **햇빛·장갑 터치 미검증**, **관측 세션 실데이터 미확보**.
- **GPS 추천은 실기 종단 검증 완료**(§7-2). 남는 것은 현장 좌표가 **미등록**된 현장뿐이며,

## 10. D6 — 조종기와 화면의 역할 분리 (2026-10-23)

사용자 피드백: 화면 정보가 많고 줄일 수 있는 설명이 공간을 차지하며,
`명령 잠김`과 조종기로 가능한 조작을 화면에 중복 구현할 필요가 없다는 지적을 반영한다.
KSI가 주 운용 앱이라는 제품 정의를 취소하는 것이 아니라 **하드웨어와 화면을 함께 운용 수단으로** 본다.

### 공식 근거와 확인 범위

공식 [DJI Dock 3 다운로드](https://enterprise.dji.com/dock-3/downloads)의
[Matrice 4D + DJI RC Plus 2 Enterprise 사용자 매뉴얼 v1.2](https://dl.djicdn.com/downloads/DJI_Dock_3/UM/20250918/DJI_Matrice_4D_Series_User_Manual_DJI_RC_Plus_2_v1.2_Enterprise_ko.pdf)
(2025-09-18 배포), **25–26쪽**을 직접 읽었다. PDF SHA256:
`04565fc2c11344fa357326d2941168f8af7a56c661a3e052deb7d8d7c5ab0550`.

| 물리 조작 | 매뉴얼에서 확인한 것 | 설계에 주는 의미 |
|---|---|---|
| 조이스틱·비행 모드 스위치 | 기체 조종 입력 수단 | 화면 가상 스틱이나 상시 비행 버튼군을 추가하지 않음 |
| RTH·비행 일시 정지 버튼 | RTH 길게 눌러 시작, 다시 눌러 취소. 일시 정지는 GNSS/비전 조건부 | 앱의 비행 요청 제한을 물리 조종기 잠금으로 표현하지 않음 |
| 녹화·포커스/셔터 버튼 | 촬영 버튼과 반누름 초점/끝까지 눌러 사진 설명 | 촬영 버튼을 기본 영상 위에 전부 중복 배치하지 않음 |
| 짐벌·카메라 줌 다이얼 | 각각의 물리 다이얼 존재/명칭 | 기본 화면의 반복 ±조작 버튼군을 접음 |
| L1~R3·C버튼/스크롤 휠 | 일부는 앱/사용자 설정에 의존 | 특정 KSI 기능으로 연결됐다고 가정하지 않음 |

이는 **공식 문서의 기능 확인**이며 현재 기체/펌웨어/KSI 앱 조합의 물리 동작 실증은 아니다.
이번 작업에서는 RC·기체 조작이나 버튼 리매핑을 하지 않는다. 실제 동작·상태 보고는 별도 실기 검증한다.

### 화면 판단

- 기본은 영상 + 간결한 필수 비행 사실 + 짧은 관측/기록 사실이다. 알려진 정상 상태의
  개발 설명·출처 진단·수신 시각·미전송 내역을 모두 상시 나열하지 않는다.
- `명령 잠김/G1b`와 비행·카메라 양쪽 버튼군은 기본 화면에서 제거한다.
  **기존 명령 게이트/포트는 유지**하며, 보조 앱 조작에 진입하거나 요청할 때만
  `앱 비행 요청 불가 · 제어 주체 미확인`처럼 범위를 밝힌다. 물리 RC가 잠겼다는 뜻으로 쓰지 않는다.
- 배터리·기체 연결·제어 상태의 미확인/지연, 관측 단절·기록 실패와 후보는 필요한 맥락에서 남긴다.
  간결화가 없는 데이터를 정상으로 만들거나 복구·대응 경로를 없애는 것은 아니다.
- 후보 대응, Edge 준비·적용, KSI 기록/동기화는 앱의 역할이다. 물리 촬영 버튼이
  KSI 세션 기록까지 대신한다고 가정하지 않는다. 세 기록 주체와 요청/실행의 구분은 유지한다.

round48의 상시 조작 레일/잠금 가설보다 이 사용자 방향이 우선한다. 이전 캡처·검증 이력은 보존한다.

## 11. D7 — 미니맵과 간결한 계기 (2026-10-23)

사용자는 현재 지도 전환이 잘 보이지 않는 경우와 지도의 애매한 사용성을 지적하고,
이전 미니맵과 더 컴팩트한 상·하단 정보를 선호한다고 밝혔다. 화면의 일은 **영상을 보며
지도 맥락을 함께 확인하고, 지도를 크게 본 뒤 같은 영상/세션으로 돌아오는 것**이다.

- 기본 영상 + 모서리 미니맵을 주안으로 구현·비교한다. 지도 확대 시에도 영상 맥락과
  명확한 복귀/접기 경로를 남긴다. 보기 조작은 비행·제어권·AI·기록을 바꾸지 않는다.
- 상단은 필요한 상태를 짧은 한 줄로, 하단은 읽기 전용의 간결한 계기 띠로 정리한다.
  조작 최소48dp를 글자/화면 전체 축소로 줄이지 않는다. 중요값·단위·미확인/지연은 보존한다.
- 지도 없음/로딩/오류/오래됨과 영상 단절은 다른 상태다. 지도 실패로 영상을 숨기거나
  복귀할 수 없는 빈 화면을 만들지 않는다. 진단용 오류 주입 버튼은 정상 운용 화면에 두지 않는다.
- 현재 웹 지도는 합성 배경·상호작용 시연이다. 실제 타일/위치/프레임 지리 정합이나
  네이티브 지도 공급사 채택을 뜻하지 않는다. 네이티브 지도 부재를 정상 지도처럼 채우지 않는다.

`captures/round32-minimap-bar/mm4-960-shown.png`(디자인 디렉터리 기준).
