## 2. 행동 계약 (불변조건)

| 행동 | 실행 주체·상태 변경 조건 | 확인 근거 | 실패·미확인 시 동작 |
|---|---|---|---|
| **경고 확인** | 사용자가 특정 경고를 확인. 앱은 확인 이력만 별도 저장 | 해당 경고에 연결된 확인 이력의 저장 성공 | 저장 실패를 알리고 확인 완료로 표시하지 않음. 위험·경고 상태는 그대로 유지 |
| **SHADOW 후보 선택** | 앱이 선택 대상과 상세 표시를 변경 | 선택한 후보의 식별자·원본 관측·출처 연결 | 자료가 없거나 오래됐으면 그 사실을 표시. ACTIVE 전환이나 장치 명령은 발생하지 않음 |
| **물리 RC 조작** | 조종사·RC·기체가 수행. 앱은 입력과 실제 결과를 관측 | 기체·SDK가 보고한 현재 비행 모드와 제어권 상태 | 조작 입력만으로 '수동 인계 완료'를 만들지 않음. 결과 수신이 없으면 이전 확인값과 미확인 상태를 구분 |
| **앱 수동 인계 요청** | 지원 기능과 현재 조건을 확인한 뒤 명령 요청 상태를 생성 | 요청에 대응하는 응답과 현재 제어권 보고를 각각 확인 | 거부 사유 표시. 응답 유실은 결과 미확인으로 유지하고 상태 조회·대조. 자동 재전송하지 않음 |
| **지도·영상 전환** | 앱의 레이아웃과 표시 대상만 변경 | 선택한 보기 상태의 반영 | 지도·영상 로딩 실패를 해당 영역에 표시. 비행·AI·기록 상태를 변경하거나 재시작하지 않음 |

불변조건:

| 행동 | 변경할 수 있는 상태 | 변경해서는 안 되는 상태 |
|---|---|---|
| 경고 확인 | 사용자의 확인 이력 | 실제 위험 상태, 경고 발생·해제 상태 |
| SHADOW 후보 선택 | 후보 상세 표시, 검토 상태 | ACTIVE 경고 상태 |
| 물리 RC 조작 | 기체가 보고하는 실제 비행·제어 상태 | 앱 요청만으로 추정한 제어권 |
| 앱 수동 인계 요청 | 명령 요청·수락·확인 상태 | 실제 확인 전 제어권 소유자 |
| 지도·영상 전환 | 레이아웃, 표시 대상 | 비행·제어권·AI 평가·기록 상태 |

## 3. 경고 상태 모델 (독립 축)

`발생 → 확인 → 해제` 직렬 구조로 만들지 않는다. 다음을 독립적으로 관리한다.

| 축 | 값 |
|---|---|
| 정책 모드 | OFF / SHADOW / ACTIVE |
| 위험 상태 | 위험 지속 / 해소 확인 / 관측 불가 |
| 사용자 확인 | 미확인 / 저장 중 / 확인 이력 있음 |

- 확인한 경고가 계속 위험할 수 있고, 관측이 끊겼다고 위험이 해제되는 것도 아니다.
- 확인 이력 저장 실패는 미확인 유지이며 위험 상태를 바꾸지 않는다.
- SHADOW 관측은 ACTIVE 안전 경보가 아니며, 경보 확인은 해제를 뜻하지 않는다.

## 4. 정보 유효성 3단계 (독립 검증)

| 표시 대상 | 필요한 근거 | 근거가 부족할 때 |
|---|---|---|
| 탐지 결과 | 원본 관측·탐지 프레임·출처 | 확인 가능한 원본 범위에서만 표시 |
| 라이브 영상 박스 | 현재 표시 프레임과 탐지 프레임의 대응 | 라이브 오버레이 보류 |
| 지도 위치·구역 관계 | 시간·자세·렌즈·지면 정합과 적용 구역 버전 | 위치·공간 판단 보류. 탐지 사실까지 지우지는 않음 |

- 하나의 `유효/무효` 값으로 합치지 않는다. "탐지는 가능하지만 지도 위치는 미확인"을 표현할 수 있어야 한다.
- 유효시간 기준은 임의의 공통 숫자가 아니라 데이터 종류·지원 조합별 검증값으로 정한다.

## 5. 상태 전이 (v1)

| 행동 | 상태 전이 | 변경하지 않는 상태 |
|---|---|---|
| 경고 확인 | 미확인 → 저장 중 → 저장 성공 시 확인됨 / 실패 시 미확인 유지 | 위험·경고 발생·해제 |
| SHADOW 후보 선택 | 미선택 → 후보 선택 → 원본 표시 또는 자료 문제 표시 | 정책 모드·ACTIVE 경고·장치 |
| 기체 상태 수신 | 마지막 확인값 보존 → 지연·미확인 표시 → 새로운 유효 보고로 갱신 | 특정 명령의 처리 결과 |
| 앱 수동 인계 요청 | 요청 대기 → 수락·거부 또는 결과 미확인 | 실제 보고 없는 제어권 소유자 |
| 지도·영상 전환 | 보기 선택 → 로딩 → 표시 또는 보기 오류 | 비행·제어권·AI 평가·기록 |

- 물리 RC 입력 이벤트를 가정하지 않고, 해당 조합에서 제공되는 실제 상태 보고를 입력으로 사용한다.
- 뒤늦은 응답은 대응하는 요청의 결과만 갱신한다. 현재 제어권이나 다른 요청의 결과까지 변경하지 않는다.

## 6. 인수 테스트 (AT)

| ID | 입력·실패 주입 | 반드시 확인할 결과 |
|---|---|---|
| AT-01 | 미확인 경고의 확인 이력 저장 실패 | 미확인 유지. 위험 상태와 경고 발생·해제 이력 불변 |
| AT-02 | SHADOW 후보 선택 후 원본 누락·자료 지연 | 자료 문제 표시. ACTIVE 상태 변경 및 장치 명령 발생 없음 |
| AT-03 | 기체 상태 보고 중단·지연 | 마지막 확인값과 현재 미확인을 구분. 물리 입력이나 시간 경과로 인계 완료 추정 없음 |
| AT-04A | 인계 요청 응답 유실 후, 새로운 수동 제어 상태 보고 수신 | 현재 제어권은 보고에 따라 갱신. 해당 요청 결과는 미확인 유지 |
| AT-04B | 이전 요청의 응답이 새 요청 이후 도착 | 이전 요청만 갱신. 새 요청과 현재 제어권 불변. 자동 재전송 없음 |
| AT-05 | 지도 로딩 실패·영상 전환 실패 | 보기 오류만 표시. 비행·제어권·AI 평가·기록 불변 |
| AT-06 | 탐지 존재, 라이브 프레임 대응 또는 지리 정합 근거 부족 | 탐지 사실 보존. 라이브 박스와 지도 위치는 각각의 근거에 따라 표시 보류 |

- 각 테스트는 결과 문구뿐 아니라 **상태 변경 범위와 발생한 외부 명령**도 검사한다. AT-04A/B 우선.
- 구현 순서: 순수 상태모델 → 실패 주입 테스트 → 프로토타입 연결 → Android/MSDK 어댑터 → 실기 검증.

## 7. 구현 원칙

1. **상태와 외부 명령 분리**: 순수 상태모델은 이벤트에 따른 상태 변경만 계산하고, 실제 저장·통신·기체
   명령은 어댑터에서 처리한다.
2. **요청별 결과 추적**: 수동 인계 요청마다 고유 ID를 부여해 응답을 연결한다. 오래된 응답이 최신 요청이나
   실제 제어권 상태를 덮어쓰지 못하도록 한다.
3. **상태 변경 범위 검증**: AT-01~06에서 기대 상태뿐 아니라 변경되지 않아야 할 상태와 외부 명령 발생
   여부까지 검증한다.
