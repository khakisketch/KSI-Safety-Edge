# 자율 안전관측 — 1단계 개발 계획 초안

상태: **2026-10-23 사용자 구현 착수 승인·호스트 통합 검증 완료. 실기 인수·ACTIVE 승인 아님.**
승인 범위는 공유 Edge/호스트 코드·증거 보존 통합이다. 동결 계약·실장비·실제 자동 조작은 변경하지 않는다.

근거: 사용자의 2026-10-23 보완 — 자동 위험관측과 능동 재관측을 독립 검증하고,
카메라 조작권과 관측 실행을 분리하며, Observation/Assessment/Action/Evidence/Incident/Alert를 구별한다.
현행 구현·인수 상태는 `../product-state.md`, 버전 정책은 `../../contracts/README.md`가 우선한다.
충돌하는 제품/역할/화면 조항은 2026-10-23 개정을 명시한다. 공개 계약 확장은 별도 버전 정책을 따른다.
현재 구현은 기존 collection artifact 경로와 내부 자료를 사용하며, 기존 실행·품질·ACTIVE 가드를 해제하지 않는다.

## 1. 이번 개발 단위

**사람의 후보 확인이나 카메라 이동 없이, 관측·평가·판정불가 처리·원본 증거화를 자동으로 마감한다.**

- 시나리오 A: 사람–중장비 위험 관측. 탐지·추적·공간/시간 근거·규칙 평가·증거화를 검증한다.
  첫 재현 사례는 기존 합의인 지정 작업구역 침입을 사용한다. 근접 거리 판정과 구역 침입은 별도 규칙이다.
- 시나리오 B: 안전모 의심 대상의 능동 재관측. **다음 독립 개발 단위**다.
  확대 필요성·카메라 요청/실제 상태·동일 대상 재식별을 모의 검증한다.
  B가 성공해도 PPE 위험 판정 정확도나 경보 승인을 입증하지 않는다. 모델·평가 자료는 별도 특정한다.
- A는 B를 호출하거나 B의 구현 완료를 기다리지 않는다. 추가 관측이 필요 없으면 Action은 0건이어도 된다.
- 기체 위치·고도·경로 변경, AI의 순찰 일시정지/취소, 실제 PSDK 카메라 조작, SDK 교체는 이번 범위 밖이다.
- KSI MSDK 앱은 유지한다. Pilot 2 방식으로의 전환이나 두 지상 앱 동시 운용을 결정하지 않는다.

## 2. 논리 기록과 생명주기

아래는 **의미 모델**이다. 6개 서비스 신설이나 승인된 wire enum·스키마를 뜻하지 않는다.

| 기록 | 최소 책임 | 자동으로 의미하지 않는 것 |
|---|---|---|
| Observation | 원본 프레임/관측 출처, 탐지·무검출·미실행·실패의 구별 | 위험·안전 판정 |
| Assessment | 입력 관측, 규칙/설정 버전, 조건 충족 여부 또는 판정불가, 품질·사유 | Incident 생성·사람의 확인 |
| Action | 추가 관측의 요청·허용·거절·실행 결과와 연결 근거 | 카메라 ACK만으로 실제 조작 성공 |
| Evidence | 보존한 원본·전후 맥락·프레임/시각/렌즈 출처·무결성·결측 | RC 수신·Core 보관 완료 |
| Incident | 승인된 위험 규칙·품질 조건에 따라 성립한 위험 사건 | 모든 탐지·SHADOW 에피소드 |
| Alert | 수신 대상·알릴 내용·생성 근거·전달 상태 | 상대방 확인·현장 조치 완료 |

- Assessment 결과와 품질, SHADOW/ACTIVE 모드, 사건/알림 생성 여부는 독립 축이다.
- SHADOW에서 조건 충족 후보를 계산·보존할 수 있으나, 이를 확정 Incident나 운용 위험 Alert로 승격하지 않는다.
- 기존 `DETECTION_EVENT`의 SHADOW 에피소드, `Track.confirmed`를 확정 위험 Incident로 재해석하지 않는다.
- 위험 Alert와 운용장애 알림은 생성 조건이 다르다. 저장 장애 등은 Incident 없이도 개입 필요 상태가 될 수 있다.
- 자동 처리 결과로 `operator-response`를 만들지 않는다. 사람의 확인·검토·현장 조치 이력은 별도로 보존한다.
- 기존 스키마에 임의 필드를 넣거나 자유문자열에 새 생명주기를 숨기지 않는다.
  공개 직렬화가 필요하면 신규 버전/확장 계약과 명시적 어댑터·검사를 먼저 제안한다.

## 3. 1단계 처리 경로

```text
명시 APPLY/START
  → 공유 SessionRunner에서 프레임·탐지·추적·입력 품질 처리
  → 원본 순환 버퍼와 관측 기록
  → 관측 묶음에 대한 Assessment
      ├ 근거 충분: 규칙 평가 결과 + 근거
      └ 근거 부족: 판정불가 + 구체적인 결측/불확실성
  → 전후 원본·평가 이력 연결
  → 로컬 내구 보존·불변 봉인
  → 기존 수집/중앙 보관 경로로 전달·영수증 대조
```

분석 실행 상태, 평가 결과, 증거 완전성, 전송 상태를 하나의 `완료`로 합치지 않는다.
관측 0건·탐지 0건·평가 불가를 서로 구분하고, 어느 것도 현장 전체의 안전 확인으로 표시하지 않는다.

## 4. 원본 순환 버퍼와 증거 완전성

- 탐지 여부와 무관하게 허용된 입력 프레임을 유한한 순환 버퍼에 보유한다.
  기존 `SourceEvidenceRecorder::Capture`의 탐지 프레임만 보존하는 정책과 분리해 설계한다.
- 후보/평가 계기에 필요한 직전 구간을 확보하고 이후 구간을 모은다.
  재확인 결과 무검출인 프레임도 평가를 설명하는 근거라면 포함한다.
- 프레임별 원본 출처·수신시각·촬영시각 검증 수준·렌즈/자세·설정 버전을 유지한다.
  수신시각을 촬영시각으로 올리거나 서로 다른 렌즈 보정값을 섞어 공간 판단하지 않는다.
- 버퍼의 시간 창·프레임/바이트 상한·선정 방식은 명시 설정과 시험 조건으로 정한다.
  수치는 대상 입력의 크기·처리율·필요 맥락을 측정한 뒤 정하며 임의 기본값으로 운영 승인하지 않는다.
- 시작 직후 직전 구간 없음, 입력 단절, 버퍼 초과, 쓰기 실패는 필요한 구간과 실제 확보 구간을 대조해 결측으로 남긴다.
  요청했다는 사실이나 파일 개수만으로 증거 완전성을 판정하지 않는다.
- 휘발성 순환 버퍼의 정상 덮어쓰기와 이미 보존한 원본 삭제는 다르다.
  봉인 원본·기존 증거는 용량 확보를 위해 지우지 않는다. 삭제 정책은 기존 dry-run 경계를 유지한다.
- 마지막 프레임 이후에도 시간 기반 마감·입력 장애 처리가 진행돼야 한다. 새 프레임 도착을 타임아웃의 전제로 두지 않는다.

보존 상태는 최소한 **Manifold 로컬 보존 / RC 수신 / Core 영수증 확인**을 별도 사실로 기록한다.
RC를 우회한 호스트 수집 시험은 RC 수신 검증으로 보고하지 않는다. Core 보관은 Alert 전달 성공도 아니다.

## 5. 관측 상태와 카메라 상태의 독립 계약

- 수동 조작으로 자동 카메라 조절 허용이 해제돼도, 유효한 입력이 있으면 분석·증거 보존은 계속한다.
- 줌/짐벌 변경 때문에 공간 근거가 무효라면 해당 평가만 보류한다. 전체 AI 관측 중지로 합치지 않는다.
- 관측 실행, 카메라 제어 주체, 자동 카메라 허용 여부, 실제 카메라 상태의 신선도를 분리한다.
  실제 제어 주체를 확인하지 못하면 `미확인`이며, 자체 요청 중재 결과를 기체의 실제 우선권으로 주장하지 않는다.
- 실제 수동 조작·DJI 임무 촬영·KSI 요청 간 우선순위와 중단 지연은 시나리오 B의 장치 인수 항목이다.
  1단계나 모의 어댑터 결과로 실기 우선권을 통과 처리하지 않는다.

## 6. 1단계 인수 기준 — 아직 실행하지 않음

| ID | 입력·상황 | 확인할 결과 |
|---|---|---|
| A01 | 명시 시작 후 유효한 지정 구역 관측 | 사람 후보 확인 0회·카메라/비행 출력 0건으로 평가와 증거 마감 |
| A02 | 공간 좌표·거리·시간 정합 부족 | 탐지 근거는 유지, 해당 공간 평가는 판정불가·사유 기록, 확정 위험 승격 없음 |
| A03 | SHADOW 조건 충족 후보·중복 프레임 | 동일 에피소드 계보와 평가 이력 유지, 확정 Incident/운용 위험 Alert 자동 생성 없음 |
| A04 | 평가 전후 구간에 무검출 프레임 포함 | 원본이 평가/전후 맥락과 연결되며, 무검출을 미실행·입력 실패와 혼동하지 않음 |
| A05 | 시작 직후·입력 중단·늦은 프레임 | 실제 확보 구간/결측이 남고, 프레임 없이도 제한 시간 내 마감·저하 표시 |
| A06 | 사람이 화각을 변경한 입력 시퀀스 | 분석은 계속, 호환되지 않는 공간 평가만 보류, 자동 카메라 실행을 추정하지 않음 |
| A07 | 메모리/디스크 상한·쓰기 실패 | 불완전/실패를 드러냄, 기존 봉인 증거 불변, 성공·안전·완전 보존으로 오표시하지 않음 |
| A08 | 중지·재시작·응답 유실·재수집 | 원본 무결성·계보 보존, 멱등 대조, 자동 실행/권한 복원 없음 |
| A09 | 로컬 봉인 후 중앙 수집 | 원본 바이트·다이제스트·참조 대조, Core 영수증의 로컬 보관 후에만 중앙 보관 확인 |
| A10 | RC 미참여 호스트 시험 | RC 수신은 미검증으로 남김. simulated 입력/기하·재생 결과와 실기 인수를 구분 |

평가 지표: 유효 관측 범위·관측 공백, 규칙별 평가 가능/불가와 원인, 근거가 연결된 평가 비율,
전후 증거 완전성, 자동 마감 지연, 사람 개입 횟수, 원본/영수증 대조 결과.
정확도·오경보·미탐·지연의 현장 목표는 별도 대표 표본/정답·운용 조건으로 정하며,
이번 호스트 합격이나 카메라 가동량을 위험 경보 승인 기준으로 대체하지 않는다.
