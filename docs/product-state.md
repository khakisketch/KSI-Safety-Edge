Android1682 중1676통과/0실패/기존6SKIP. 운용 RC는 변경하지 않았고 실영상·장비 종단·현장/디자인 인수와 별개다.

**2026-10-29 개발 후보:** 임무 목록에 저장된 구역·규칙 내용을 표시하고, 지난 결과와 KSI 기록
종료에서 해당 기록 상세로 연결한다. 비행 장애의 원인·조치와 설정의 기체/MOP/영상/서버 출처를
구분하고, 세션 없음·관측 미수신·모드 미확인을 후보 없음이나 SHADOW로 단정하지 않는다.
격리 사본의 호스트 검증은 Python **228건 통과**, Android ports **94**·core **279**·MSDK **106**·
앱 bench **646건 중 6건 SKIP**·앱 device **624건** 실패 없음이다. bench APK 빌드와 device Kotlin
컴파일도 성공했다. 의존성 캐시를 사용한 Linux aarch64 검증이며 새 native 렌더·768×464dp/글꼴
1.3 실측·실영상·실기·사용자 인수는 확인하지 않았다. 운용 앱 설치나 실제 장비 명령도 하지 않았다.
JDK 17을 지정한 비서명 bench/device 릴리스 APK 로컬 위생 검사는 각각 **18/18 통과**했으며,

**MOP 핀 정합:** 기존 `main`의 고정 Edge→RC fixture와 현재 Edge 코드의 `MISSION_STATUS.running`
값이 다르다(APPLY 후 기존 `true`, 현재 `false`). 동결된 fixture를 유지한 채 현행 producer가 기존
바이트를 만들어야 한다고 비교하면 `mop_e2e`가 실패했다. **10-29 사용자 결정:** 기존 바이트를
보존하고 현행 출력은 별도 자료로 고정하여 이 사례의 producer 동일 출력 보장을 대체한다.
동결된 자료와 별도 현행 핀을 함께 사용한 격리 C++ 시험은 **41/41 통과**했다. 옛 자료 수신과
시작·중지 회귀는 별도 검증하며 혼합 배포 전체의 호환성이나 실기 승인을 뜻하지 않는다.

## 인수 사다리와 미완료

| 단계 | 의미 | 현재 판정 |
| --- | --- | --- |
| L1 | 실제 탐지·오프라인 저장·재시작·재연결·Core 조회 | 부분 장비 관찰과 코드/Replay는 있지만 **통합 제품 인수 미완료** |
| L2 | 대표 조건·독립 GT와 calibration/holdout으로 SHADOW 오차 평가 | 실측 평가 미완료 |
| L3 | 검증된 조건·규칙에서 제한 위험 경고 | **ACTIVE 비활성**, 규칙별 별도 승인·롤백 게이트 필요 |

M0 설계 기준선과 M1 Replay 완료, M2 코드·Replay 및 M3 합성 SHADOW, M4 ACTIVE 대기의
상세 마일스톤·당시 시험 수는 이전 원장에 비공개 보존한다.
호스트·시뮬레이션·실기 관찰·사용자 인수·보안 게이트는 서로 대신하지 않는다.

다음 제품 방향은 10-23 합의대로 **새 기능보다 실제 장비 통합·현장 사용성 입증**이다.
현재 배정 과업과 최근 증거는 native 현황·해당 작업 기록을 따르고, 이 요약이 이를 재배정하지 않는다.
장비 접근·명령·배포·ACTIVE는 각 현재 사용자 승인 범위를 확인한 뒤 수행한다.
round86/a16 HUD 설정, round87/a17 카메라 상세·감지·지도, round88/a18 상세 전체 화면은 실제 RC에 설치·검증했고, 비행 명령·ACTIVE·서비스 설정은 변경하지 않았다.

## 원칙과 외부 입력

1. Edge→서버 직접 업로드 금지. RC가 업로드 주체이며 별도 승인 수집 경로와 구분한다.
2. 라이브 DJI 영상과 Edge 추론 프레임을 동일 프레임으로 가정하지 않는다.
3. VLM/LLM은 비행 후 검토만. 실시간 판단 참여 금지.
4. 원본 탐지·운영자 의견·사후 의견·검증 라벨은 분리한다.
5. 사건0건은 안전이 아니다. 관측 공백·미확인·지연을 명시한다.
6. 원본 snapshot·승인 계약·검증 증거는 보존한다. AI 장애가 기본 비행·수동 카메라를 막지 않는다.
7. 독립 디자인 시안의 입력·자산 출처와 검증 한계는 보고서/메타데이터에 기록하고 시안 배지를
   요구하지 않는다. 연결된 앱의 시험 입력과 실제 보고는 계속 구별한다(화면 계약 D9).

실기 통합에는 해당 RC/개발자 디버깅·우리 앱 키·Manifold 접근/설치·기동 승인과 실제 입력이
필요하다. 예전의 “기기 없음”을 현재 접속 사실로 재사용하지 않는다. 현장·날짜·장비/렌즈·독립 GT,
인증/조직 권한·Keystore/네트워크 보안·보존/백업의 결정은 관련 인수·보안 문서를 따른다.
앱 키는 `android-rc/local.properties`의 `dji.apiKey`에만 두고 채팅·커밋하지 않는다.
