# 프로젝트 지침 정합화 — 2026-10-25

## 결과와 범위

프로젝트 내부에 실제 지침 충돌·스킬 연결 결함이 있었다. 사용자 승인에 따라 현행 지침과 이력을 분리했다.
**이것이 디자인 품질 부족의 유일한 원인이거나, 정리 후 전문적인 디자인이 보장된다는 뜻은 아니다.**
이번 작업은 지침/메타데이터 정합화다. UI·제품 코드·계약 스키마·기기·서버·전역 설정·모델을 변경하지 않았다.
현재 화면 기준선은 a11이며, 사용자 평가에 인용된 a10과 구별한다. a11의 일부 배치 보정이 전체 구성/카메라 경험의
완성을 뜻하지 않는다. 당시 UI/설치 증거는 `design/rc-pilot-shell/round78-verification.md`다.

## 도구·모델·하네스는 어디까지 판단할 수 있는가

- **도구/스킬 활용:** 도구가 없었던 것이 아니라 브리프 연결·현재 플랫폼 문서·검토 질문의 사용 방식이 부족했다.
  과거 브리프를 수동으로 읽은 사실도 있으므로 자동 선택 실패가 모든 맥락을 잃게 했다고 과장하지 않는다.
- **작업 판단:** 사용자 지적 항목의 변경 여부만 확인하는 검토는 전체 구성의 적합성을 입증하지 못한다.
  프로젝트 정리는 그 판단 책임을 없애지 않는다. 신규 [RC 전체 화면 검토](rc-design-review.md)는
  레퍼런스 원리→제품 결정→대안/이유→전체 렌더의 연결과 장면/시간/배선의 별도 증거를 요구한다.
- **모델 수준:** 이전 Engineer 호출에 `Model unavailable` 실패가 있었고 해당 카메라 수신 단위는 구현되지 않았다.
  이는 실행 경로 실패 증거이지 모델의 디자인 능력 비교 실험이 아니다. 같은 과제/입력의 A/B 평가는 하지 않았다.
- **설정 위치:** 저장소와 `.opencode/`에서 프로젝트 모델/에이전트 override는 발견하지 못했다.
  전역 정의의 모델 참조는 읽기 전용으로 확인했지만 변경하거나 우회/자동 fallback을 만들지 않았다.
  공급자 장애 원인·현재 가용성·세션별 실제 모델 선택은 이 문서의 확정 범위가 아니다.
- **하네스:** OpenCode V2 공식 문서는 지침을 합치며 충돌을 자동 해결하지 않는다고 설명한다.
  따라서 전역 개선과 별개로 남은 프로젝트 문장을 정리할 이유가 있다. 이번 정적 조사로 하네스 전체의 결함/정상을 판정하지 않는다.

공식 근거: [V2 instructions](https://opencode.ai/v2/docs/instructions),
[V2 config](https://opencode.ai/v2/docs/config). 설치된 Impeccable의 doctor/document/surface-brief 지침도 직접 대조했다.

- DESIGN은 현행8개 표준 절만 사용. B-1의 상태/행동/권한 구간은 원본과 동일.
- 제품 소스·계약·보호 증거568파일의 경로 집합/해시 전후 동일. 기기 접근·앱 재설치·테스트용 명령 전송 없음.
- 독립 Critic은 지침 일관성 범위에서 새 material 결함0건을 관찰했다. 전체 UX 인수는 아니다.
- doctor의 사이드카 stale 항목은 해소됐다. 이것을 모든 스킬 설정/디자인 품질이 검증됐다는 뜻으로 쓰지 않는다.

문서/메타데이터만 바뀌었으므로 앱 빌드·실기 시험을 새로 실행하거나 과거 통과 수를 이번 실행 결과로 재사용하지 않았다.
정리의 성공 기준은 **현재 지침이 실제 대상에 연결되고 충돌을 줄였는가**다. 다음 UI 작업의 성공 기준은
그와 별개로 **전체 화면과 시간에 따른 운용 경험이 실제로 좋아졌는가**다.
