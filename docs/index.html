해결하려는 문제

네트워크가 없는 현장에서도 사람·중장비 관측 기록이 끊기지 않고, 연결 복구 후 당시 설정과 증거를 그대로 조회할 수 있어야 합니다.

현재 확인된 근거

재생 하네스에서 임무 적용 → 오프라인 기록 → 재시작 복원 → 업로드 → 조회 전 구간과 장애 시나리오(E01~E12)를 재현합니다. Python·C++·Android 3축 CI가 main 푸시마다 실행됩니다.

현장 적용 전 남은 것

실제 기체·RC 실기 검증, 사용자 인수, 운영 인증·권한·HTTPS 게이트입니다.

시스템 구성

Edge · 기체 탑재

Matrice 4 + Manifold 3. 사람·중장비 탐지·추적·공간 분석 (C++, PSDK, ONNX/TensorRT)

RC · 조종기

오프라인 기록·미션 적용·복구 후 업로드. 유일한 업로드 주체 (Android MSDK, Kotlin, SQLite WAL)

Core · 서버

증거 수집·데이터 점검·의견 기록(개발·검증용) (Python FastAPI)

설계된 현장 운용 흐름

아래는 설계된 운용 흐름(목표 동작)입니다. RC→Core 전송의 종단간 검증은 별도 절차이며, 실기 검증·사용자 인수 전입니다.

① 임무 준비
사이트·미션 번들·구역 정책을 RC에 동기화하고 Edge에 적용합니다.
② 비행 관측
네트워크 없이도 탐지·추적·공간 관측을 수행하고 RC 로컬 DB에 영속 기록합니다.
③ 증거 동기화
연결 복구 후 업로드 큐가 재개·중복방지·무결성 검증과 함께 Core에 전송합니다.
④ 데이터 점검
업로드 상태·관측 커버리지·사건별 근거·증거 원본을 조회합니다 (운영자 검토 서비스는 별개).

아래는 이해를 돕기 위한 가상 시나리오와 개념도입니다. 특정 실현장을 지칭하지 않으며, 실기 검증·사용자 인수 전입니다.

화면 소개

아래 화면은 시연 환경 캡처이며, 화면의 [SIMULATED] 표기를 유지합니다. 현장명은 예시(SIM-FLT-024 등)이며 특정 실현장을 지칭하지 않습니다.

기술적 특징

  • 계약 우선 설계 — JSON Schema 13종 + OpenAPI 40여 개 오퍼레이션으로 Edge/RC/Core 경계를 고정하고, Python·C++·Kotlin이 동일 계약으로 검증됩니다.
  • 결정적 재생 하네스 — 장비 없이 전 구간과 장애(E01~E12: ACK 유실·중복·역순·중단재개·손상정정·교차조직 차단 등)를 재현합니다.
  • 3축 CI — 모든 main 푸시마다 Python + Edge C++ 빌드/테스트 + Android 단위테스트·벤치 APK를 검증합니다.
  • 무결성 보장 — 멱등 ingest·digest 검증·감사 로그·교차 조직 접근 시 존재 여부 비노출(404) 원칙.

source .venv/bin/activate
bash scripts/run_all_tests.sh    # Python 테스트 전체 (contracts·libs·core·harness)
