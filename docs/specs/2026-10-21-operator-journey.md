## 사용자의 업무와 화면의 역할

현장 조종자는 비행 안전을 유지하면서 자동 관측이 유효하게 진행되고 원본이 남는지 감독하고,
필요한 예외에만 개입한다. 기본 운용은 **하나의 KSI 앱**에서 이어지고 첫 화면은 관측/비행이다.
별도 홈 화면이나 Pilot 2 왕복을 필수 흐름으로 추가하지 않는다. 엔진은 지상 앱에서 독립한다.

| 단계 | 화면 책임 | 핵심 행동·남는 사실 | 구현·검증 경계 |
| --- | --- | --- | --- |
| S0 현장·구역 지정 | 관측에서 현장 확인/선택 → 준비의 구역 설정 | 현장·지도 캐시·로컬 불변 구역·Edge 적용을 구분 | 지도 점찍기·타일 공급사·현장 정합은 미완료. 현장 인식 실패로 일반 비행을 잠그지 않음 |
| S1 순찰 준비 | 준비 화면 | 동기화→번들 선택→준비→적용→기록 시작. 실제 APPLIED와 저장 공간·관측 조건 확인 | 준비/적용/시작 응답을 합쳐 거짓 준비 완료를 만들지 않음. 현재 버전의 실기 종단은 별도 |
| S2 비행·관측 감독 | 영상·지도 중심의 비행 화면 | 필수 비행 사실, 실제 관측/입력 품질, 카메라 제어 주체, 원본 보존과 중요한 개입 사유 | native a14/a15의 제한된 실측과 실영상·지도·AI 정합·현장 운용을 구분 |
| S3 자동 평가·선택적 예외 대응 | 비행을 가리지 않는 중요 문제/기록 상세 | Edge가 평가·판정불가·원본 증거화. 사람의 확인/보류/전달·메모는 선택적 append | 자동 평가로 사람 응답·현장 조치를 만들지 않음. 위험 Alert는 별도 정책/승인 |
| S4 기록 검토 | 기록/근거 화면 | 당시 설정·관측 품질·원본 근거와 전송 상태 대조 | 로컬 검토 준비와 중앙 보관은 별개. 미수신·누락을 안전/완료로 표시하지 않음 |
| S5 중앙 보관 | 전송 관리·보관 상태 | 연결 시 전송/재시도·Core 영수증 확인 | 사람 검토·세션 종료를 선행 조건으로 두지 않음. Core 영수증은 보관 증거이지 삭제·알림 수신 증거가 아님 |
| S6 기기·설정 | 연결·권한·저장·진단 상세 | 비행 전 확인과 비행 후 복구 | 기기/서버 사실을 구분하고 현재 보고가 없으면 미확인 |

S0~S6는 화면 책임의 연결이지 항상 모두 거쳐야 하는 잠금 순서가 아니다. 일반 비행 진입은
현장 선택 없이도 가능하되 공간 판정은 필요한 현장 정보가 있어야 한다. MOP의
PREPARE/APPLY/START 및 명령별 게이트를 우회한다는 뜻은 아니다.

## 기본 화면에서 답할 질문

- 관측이 실제로 진행되는가? 요청 접수·`running`만으로 분석 중이라 하지 않는다.
- 카메라를 누가 조작하는가? 수동 양보·자동 조절 허용·실제 조절과 AI 관측 실행을 분리한다.
- 원본이 남는가? Manifold 내구 보존·RC 수신·Core 영수증은 독립 축이다.
- 지금 개입해야 하는가? 중요한 장애/승인된 위험과 필요한 행동은 보이되 매 후보 검토를 강제하지 않는다.

영상·필수 비행 사실·현재 과업을 우선하고 진단·해시·처리 이력은 상세에서 확인한다.
물리 스틱·줌/짐벌·REC/촬영 버튼을 화면에 전부 복제하지 않는다. 앱 요청 불가를
물리 조종기 잠금으로 표시하지 않는다. AI 장애가 기본 비행·수동 카메라를 막지 않는다.
특정 라운드의 카드 수·폭·픽셀·고정 띠는 제품 계약이 아니며 현재 native 표현은
[`../../design/rc-pilot-shell/README.md`](../../design/rc-pilot-shell/README.md)와 `DESIGN.md`를 따른다.

## 실패·복구와 상태 구분

- 영상/지도/통신/입력 단절은 구분한다. 마지막 관찰값을 현재 정상값으로 보이지 않게 한다.
- 준비 미완은 미완인 축을 밝히고, 요청 ACK와 실제 적용·관측·녹화/저장 성공을 구분한다.
- 관측0건·사건0건은 안전이 아니다. 일반 판정불가·공백과 중요한 저장/관측 장애를 구분한다.
- 선택적 사람 대응은 출처가 해결될 때만 append하고 기존 관측·사건을 수정하지 않는다.
- 현장 검토 준비는 정확한 리비전·디코딩 가능·링크 및 원본 바이트/해시가 필요하다.
  서버 미조회는 “확인 못 함”이지 “서버에 없음”이 아니다.
- 중앙 보관은 로컬에 영수증이 남은 뒤 확인한다. PARTIAL≠완료, 동일 manifest 재시도는 멱등이다.
- 카메라 read-only 보고의 실제 렌즈/배율 관찰을 물리 REC·사진 저장·현장 인수로 확대하지 않는다.
- SHADOW와 위험 경고 ACTIVE는 다르며 실측·규칙별 승인 전 승격하지 않는다.

Core 원본 수집 receipt는 현재 코드/호스트 경로가 있으므로 예전 “미설계” 설명을 되풀이하지
않는다. 반대로 이를 현재 실 Edge 수집·복구 종단 통과로 주장하지 않는다. 세부 상태는
제품 원장과 해당 검증 기록을 따른다.

## 인수에 남길 결과

준비·적용→실제 관측/원본 기록→오프라인 보존→앱/Edge 재시작 복원→단절/재연결·동일 메시지
재전송→RC 업로드 COMMITTED→Core 조회·대조를 실제 승인된 장비/입력으로 확인한다.
중요 장애·저장 실패·관측 공백, 기본 비행/수동 카메라 지속성, 영상/상세 전환 후 복귀도 포함한다.

웹 합성·Android 호스트·native 렌더·물리 조작·실기 전체·사용자 인수는 서로 다른 증거다.
768×480dp와 usable 768×464dp, 주야간·장갑·햇빛·48dp 조작·접근성을 대상 환경에서 확인한다.
현재 정리는 새 실기 접근이나 자동 카메라·AI 비행·ACTIVE 권한을 만들지 않는다.

미구현 상태는 현행 지시가 아니다.
