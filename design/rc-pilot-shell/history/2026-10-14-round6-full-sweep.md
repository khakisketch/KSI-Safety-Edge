## 사용자 과업과 제안

조종자는 비행 전 KSI 기록 준비를 확인하고, 비행 중에는 DJI Pilot 2 조종을 방해받지 않으며, 비행 후에는 로컬 기록·사건·증거·동기화 사실을 구분해 확인한다. 라운드 6은 기존 차분한 조종 화면을 유지하고 나머지 화면의 단계·상태·다음 행동을 더 분명히 연결하는 전 화면 개선으로 진행했다.

| 사용자 과업 | 구현 제안 | 결과 |
|---|---|---|
| 비행 전 준비·기록 시작 | 메뉴를 `비행 전 준비 / 비행 후 검토 / 로컬·동기화 / 앱·조종사` 흐름으로 명확화. `로컬 기록 시작`을 주 동작으로, 관측 세션 보조 동작과 종료 동작은 보조 위계로 분리. | 조종·임무 준비는 한 화면에 유지; 실제 기체 비행 제어로 오인할 문구는 추가하지 않음. |
| 임무 동기화 결과 해석 | 동기화 요청 뒤에도 화면 내 상태 문구를 유지하고 서버 호출 없음·결과 알 수 없음을 명시. | 토스트가 사라져도 정직한 상태 설명은 남음. API/네트워크 동작은 추가되지 않음. |
| 임무 리비전 확인 | 실제 리비전 ID와 번들에 고정된 임무 구성이라는 설명을 함께 노출. | 스키마가 제공하지 않는 사람이 읽는 리비전 이름은 만들지 않음. |
| 비행 후 기록 검토 | 시작/종료/소요시간 필드를 분리. 완료 예시의 시간은 RC 수신시각 간격으로, 활성 기록은 종료·시간을 알 수 없음으로 유지. | 0건 비행은 별도 상태이며 의견 입력은 비활성. `사건 0건 ≠ 안전 확인`을 유지. |
| 로컬 증거와 서버 동기화 구분 | 로컬 완전성을 `완료 / 부분 / 알 수 없음`으로 표현하고 동기화 상태는 계속 `미동기화`로 분리. 업로드 게이트는 Core URL+토큰이 없으면 비활성. | 서버 상태·업로드 완료를 추측하지 않음. 실제 저장/업로드를 시연하지 않음. |
| 작은 화면에서 증거 표 확인 | 모바일의 좌우 스크롤 안내를 추가하고 포커스 후 ←/→ 키로 움직이는 동작을 제공. | Evidence와 비행 후 Evidence 표에서 키보드 수평 스크롤 확인. |
| Android 문구 정합 | 기록 시작/종료, 화면 제목, 미션 리비전 ID의 표시·접근성 설명, 기록 소요시간을 HTML의 사실 경계에 맞춤. | `MainActivity.kt`와 `strings.xml`만 변경; 레이아웃 파일·API·권한·비즈니스 동작은 바꾸지 않음. |

## 의도적으로 유지·거절한 변경

- 조종 화면의 영상 중심·무박스 상태 띠를 유지했다. 추가 대시보드 카드나 비행 중 사건 판단을 넣지 않았다.
- 시뮬레이션이 실제 비행, 인터넷, 서버 업로드 또는 Core 저장을 성공했다고 표현하지 않는다.
- 미션 리비전 이름을 임의 생성하지 않았다. `SIM-REV-A-003`은 예시 ID이며 번들에 고정된 임무 구성 ID라는 설명만 추가했다.
- 로컬 완전성과 동기화를 한 상태로 합치지 않았고, 서버 상태를 `완료`로 추정하지 않았다.
- 0 사건을 안전 판정으로 바꾸지 않았으며, RC 수신시각의 근사성을 실제 촬영시각으로 승격하지 않았다.
- 단계 번호는 비행 전/후 흐름을 가리키므로 유지했다. Impeccable detector가 번호 라벨 advisory를 냈으며, 이는 별도 사용성 확인 항목으로 영수증에 기록했다.
